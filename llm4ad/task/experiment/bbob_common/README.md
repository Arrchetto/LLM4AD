# BBOB Experiment Task

This directory contains the shared BBOB (Black-Box Optimization Benchmark) evaluation protocol used by both EoH and LLaMEA tasks in `llm4ad/task/experiment/`.

## Goal

Evolve complete black-box optimization algorithms for the BBOB noiseless suite in 5 dimensions, using the Area Over the Convergence Curve (AOCC) as the anytime performance metric.

## Benchmark

- **Suite**: BBOB noiseless functions `f1`–`f24`.
- **Dimension**: fixed at `dim = 5`.
- **Search space**: `[-5, 5]^d`.
- **IOH constructor**: `ioh.get_problem(fid, instance, dimension=5)`.

## Instances and Seeds

Each function is evaluated on:

- **3 instances**: `[1, 2, 3]`
- **3 random seeds per instance**: `[0, 1, 2]`

Total runs per algorithm: `24 × 3 × 3 = 216`.

These configurations are generated by `suite.make_bbob_training_set()`.

## Evaluation Budget

- `budget = 10_000` function evaluations per run.
- The candidate algorithm must return a best-so-far history of length ≤ `budget`.

## Performance Metric: AOCC

**AOCC** (Area Over the Convergence Curve) is a normalized anytime performance measure:

- Range: `[0, 1]`, **higher is better**.
- Precision bounds: `lb = 1e-8`, `ub = 1e2`.
- Precision values are log-scaled before normalization.
- Final score is the mean AOCC over all 216 runs.

## Fitness Output

Both evaluators return the **positive aggregate AOCC**:

- `bbob_eoh_full.BBOBEoHEvaluation` returns AOCC directly (EoH maximizes fitness).
- `bbob_llamea_class.BBOBLLaMEAClassEvaluation` returns AOCC directly (LLaMEA maximizes fitness).

Approximate reference values for `dim = 5`:

| Algorithm | AOCC |
|---|---|
| Pure random search | ~0.09 |
| Random search + local perturbation baseline | ~0.19 |

## Implementation Constraints

- Maintain two separate variables:
  - `best_value`: scalar best objective value found.
  - `best_x`: 1-D numpy array of length `dim` where that value was found.
- Perturb `best_x` for local search, never the scalar `best_value`.
- Evaluate exactly one fresh candidate per loop iteration.
- Append exactly one value to `history` per iteration.
- Do **not** use pure grid search in 5D; the grid size grows exponentially and exceeds the budget.

## Paper Setting

This setup follows the LLaMEA paper (van Stein & Bäck, 2025):

- BBOB noiseless functions, `d = 5`.
- 3 instances per function.
- 3 independent runs (seeds) per instance.
- Budget `B = 10_000` function evaluations per run.
- Aggregated mean AOCC as the single fitness value.
